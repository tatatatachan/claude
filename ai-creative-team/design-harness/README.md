# デザインハーネス(Design Harness)

AI創造チーム(CD / AD / 制作 / サムネ担当)に、**「デザインハーネス」**の考え方を取り入れたもの。2026-10-25 に世界の資料を調べ、そのうえで設計した。調査の原文メモは [research/](research/)。

## 1. デザインハーネスとは(調べて分かったこと)
- **ハーネス(harness)** = AIエージェントの「モデル以外すべて」。指示ファイル、ツール、検証、承認、ログなど、AIを意図した形につなぐ環境。「Agent = Model + Harness」(LangChain Trivedy、2026-03。[出典](https://www.langchain.com/blog/the-anatomy-of-an-agent-harness))。ハーネスエンジニアリングという言葉は2026年初めに広まった(Hashimoto 2026-02: エージェントが間違うたびに、二度と起こらないよう規則かツールを足す。[出典](https://mitchellh.com/writing/my-ai-adoption-journey))。
- **デザインハーネス** = その考え方をデザインに当てはめたもの。「デジタルプロダクトやサービスのデザインをAIエージェントと一緒に進めるための仕組み」(こぎそ 2026-08)。日本の実務家が2026年5月ごろから使い始めた用語と見られる(最初の定義記事は取得できず、間接情報から)。**標準の定義はまだない。** 英語圏で同じ語を使う一次情報は、今回の調査では見つからなかった。
- **よく使われる4層**(デザペディア 2026-06、こぎそ 2026-07): ①制約(Constraints) ②文脈(Context) ③検証(Verification) ④評価(Evaluation)。
- 共通する考え方: **判断基準を言語化して機械が読める形にし、AIの出力を機械検証で囲み、最終判断は人に残す。**

## 2. 世界の資料から決めた設計方針(根拠の強さつき)
| # | 方針 | 根拠 | 強さ |
|---|---|---|---|
| 1 | **制作と評価を別のAI・別のセッションにする。** 自己採点は甘い | Anthropic: エージェントは自作を過大評価し、特にデザインで顕著。評価役を懐疑的に調整する方が、生成役を自己批判的にするより扱いやすい([出典](https://www.anthropic.com/engineering/harness-design-long-running-apps)) | 中(1社の報告、自社製品の文脈) |
| 2 | **主観を採点基準に分解し、見本(アンカー)で較正する** | 同上: デザイン品質・独自性・クラフト・機能性の4基準、詳細なスコア付きfew-shotで人の好みに合わせた。独自性は「テンプレ・AI定型」を減点 | 中 |
| 3 | **間違いのたびに、規則かツールを1つ足す** | Hashimoto 2026-02。Lazy Director(自作の画像検査で、崩れのたびにルールを1行足す) | 中(個人の実践) |
| 4 | **決定的な検査を先に、AIの主観評価は後に** | Trivedy: 決定的に実行するフック。Lazy Director: 画像端のピクセル検査。ただし**サムネ(画像)向けの標準ツールは見つからなかった**ため自作 | 弱〜中 |
| 5 | **ルールは短い地図+詳細ファイル(段階的開示)** | Trivedy、OpenAI(検索スニペットのみ・未確認) | 弱 |
| 6 | **人が評価役のログを読み、ズレを見つけて基準を直す** | Anthropic: 評価役が自分を説得して合格にする問題を、ログを読んで改善 | 中 |
| 7 | **AIの評価は人の代替にしない** | 「MLLM as a UI Judge」: 人との一致は約60%(僅差では低い)。著者も代替でなく近似と結論 | 中(UI画面での結果。サムネは未検証) |
| 8 | **構成要素は定期的に外して検証する** | Anthropic: 各構成要素は「モデルが単独でできないこと」の仮定を持つ。モデルの更新で不要になる | 中 |
| 9 | **小さく始める。反復は3回から測る** | こぎそ・Lazy Director・Zenn: 原則3〜5個から。Anthropicは5〜15反復で頭打ちを報告(画面開発) | 弱 |
| 10 | **ブランド・画像は検証をコードに置きにくい。らしさの定義は人が決める** | こぎそ 2026-07。広告業界でも、ブランド準拠チェックの中身(合否基準・精度)を公開している例は少ない(Scenarioの品質ゲートのみ数値公開、ベンダー記事) | 中 |

測定値の注意: 効果の数字(クラシル 20→100%、グッドパッチ 3日→3時間、Atlassian のトークン比較など)は、**小規模・社内測定・自己申告**のものばかり。第三者検証は見つかっていない。デザインハーネスが効くという**強い証拠はまだない**。

## 4. 動かしてみた結果
- `validate.js` は、悪い例(白地に白字、重なり、極小文字)を正しくFAILにし、直した試作7枚はFAILなし(PASS 3、WARN 4。WARNは端から4%以内の文字と、文字の多さ)。試作を作る途中で私が目で見つけた不具合(数字と氏名の重なりなど)も、同じ種類の検査で拾える。
- `dupcheck.py` を虎ノ門広告祭のKVに当てた結果、**画像の使い回しを自動で検出**した: 2026年は3組(ART&COPY上映会の2枚、OPEN BARの体験とセッション、toracoyaのDAY4/DAY5=違いはDAY表記だけ)、2025年は7組(ART&COPY上映会3枚、キーノート2枚ほか)。目視評価で見つけていた問題と一致した。
- 限界: これらは**規約の遵守と崩れ**を見るもので、**美しさや独自性は測れない。** それは④の評価役と人が担う。評価役のAIの採点が人とどれくらい合うかは、**まだ測っていない**(次の課題)。

## 5. まだ分かっていないこと
- 評価役AIと人の採点の一致度(サムネ・ポスター)。検品会のデータで測る必要がある。
- サムネの検査項目の妥当性(例: 一覧での最小文字サイズの基準 8px は私の仮置き)。
- ブランド準拠チェックの標準(Adobe・Canvaの機能は仕様を確認できなかった)。
- 採用物でAI生成画像を使うときの開示ルール(EU AI Act 第50条は2026-08-02適用。日本の採用物向けの指針は見つからなかった。法的助言ではないので、弁護士確認が必要)。
