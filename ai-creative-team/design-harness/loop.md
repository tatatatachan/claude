# 制作ループ(デザインハーネスの運用)

```
CD ブリーフ → 制作(HTML/CSS) → 検証(自動) → 評価(別のAI) → 人が判断 → 記録 → ルール追加
```

1. **ブリーフ(CD)**: [context/brief-template.md](context/brief-template.md) を埋める。足りない情報は人に質問する(推測で埋めない)。
2. **制作(AD/制作役)**: [context/brand-sheet.md](context/brand-sheet.md) の固定値で、HTML/CSSかFigmaで組む。**方向性の違う案を2〜3つ**作り、PNGで書き出す。
3. **検証(自動)**: `node design-harness/validate.js 案.html`(縦は `--w 1080 --h 1920`)と、シリーズなら `python3 design-harness/dupcheck.py 画像フォルダ`。**FAILが残る案は、評価に出さず直す。**
4. **評価(別のAI)**: [evaluator.md](evaluator.md)。制作側の説明は見せない。点数と、直す点(最大3つ)を受け取る。
5. **差し戻し**: 直す点を反映して2〜4を繰り返す。**最大3周**(初期値)。3周で届かなければ人に相談する。頭打ちの周回数は記録し、上限を見直す。
6. **人が判断**: 採用/不採用と理由を決める。**評価役の点が、人の感覚とズレたら、そのズレを記録する。**
7. **記録**: [../learning-log.md](../learning-log.md) に、日付・案件・採用/不採用・理由・ズレを1行。
8. **ルール追加**: 同じ種類の差し戻しが出たら、[rules.md](rules.md) に1行足す。自動にできるなら validate.js に足し、tests/ に悪い例を足す(`sh design-harness/tests/run.sh`)。
9. **月に1回**: ルールを1つずつ外して、品質が落ちるか確かめる(不要になった仮定を減らす)。

## 役割
| 役割 | やること | やらないこと |
|---|---|---|
| CD | ブリーフ、コンセプト案3つ、事実の裏取り | 見た目の細部 |
| AD/制作 | 固定値で組む、案を複数出す、検証を通す | 自分の案の採点 |
| 評価役 | 画像だけを見て、欠点を先に出し、採点する | 制作、直接の修正 |
| 人 | 最終判断、較正、ズレの発見、らしさの定義 | — |

## コストの目安
画像生成の反復コストは未測定。Anthropicの報告(コード生成)では、単独で $9 の作業が、評価役つきのフルハーネスで $200 になった。**評価役は、モデルが単独で確実にできる範囲を超える作業にだけ使う**(簡単な案件は、検証(自動)と人のレビューだけでよい)。
