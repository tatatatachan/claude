# SPDシートの概念（社内資料からの整理）

出典：Notion「Dir基礎講座『HOW TO MAKE』」、Drive「【テンプレ】SPDシート」「【テンプレ】ドキュメントver.SPDシート」、鹿島南共同発電のSPDシート（v1・v2）、Slack（#visions-project、#2026-ディレクター基礎講座-実践編 ほか）。
SPDという略称の正式な展開は、確認できた資料に書かれていません。ここでは書かれていることだけを整理しています。

## 1. SPDシートとは
- ディレクターが書く、企画の設計書。取材で聞いたことや調べたことを整理し、「何を言うか」「どう言うか」までを1つにまとめる。
- チームで共有するときの共通言語。SPDを使うとコミュニケーションのスピードが上がり、そのままPPTに入れてプレゼンでき、企画書づくりも早くなる。
- SPDシートを書いた人がチームの中心（ディレクター）になる。アシスタントディレクターのときも書いてみるとよい。
- 役割：CD＝クオリティの責任者（セーフティーネット）／Pr＝全案件のヒト・モノ・カネの責任者。VISIONとコンセプトの決定は CD・Pr。
- 姿勢：お客様の言ったことをそのまま作らない。基本は美点凝視。相手を好きになれないと仕事にならない。
- 順番：相手のニーズを知るところから。1枚目と2枚目の左側（ヒアリングと課題）をしっかり書かないと、Bがふわっとした理想になる。

## 2. 3ページ構成（テンプレートの型）

| ページ | 中身 | 問い |
|---|---|---|
| 1ページ目 HEARING → VISION | ①Hearing Sheet：企業・事業の内容（理念／組織／採用）、事実、先方の言葉。②Project Vision：どんな変化をつくりたいか（Before → After） | 取材の内容や調べた情報をまとめ、生み出したいBefore/Afterを決める |
| 2ページ目 課題 → CONCEPT | ③Concept Making：SEEDS（企業のらしさ）×NEEDS（ターゲット：ペルソナ・インサイト）。顕在的な課題・潜在的な課題。つよみや資産。ターゲットのメリット。コンセプト（What to say） | 誰に、何を伝えるのか |
| 3ページ目 表現 | How to say：世界観、ワンワード（スローガン）、ワンビジュアル（任意）、表現コンテンツ（1Dayか長期か、当日の流れ） | どう言うのか |

### 項目の定義（テンプレートの言葉）
- **SEEDS**：企業のらしさ。事実（歴史・ビジネスモデル・サービス・商品・現場の工夫）と、価値観（大切にしている想い・スタンス）。
- **NEEDS**：メッセージを届けたい人。ペルソナ→インサイト。
- **ターゲットのメリット**：SEEDSのうち、ターゲットが最も魅力的に思うこと。伝えた後に呼び起こしたい感情・読後感。
- **コンセプト**：目的を達成するための企画の方向性。つまり何を伝えるのか、要は何をするのか。
- **ドキュメント版の項目**：このプロジェクトのVISION／企業・事業の概要／課題（顕在・潜在）／つよみや資産／ペルソナ／コンセプト／世界観／ワンワード／できそうなこと。

## 3. 運用の約束（鹿島南共の事例から）
- VISION・コンセプトは3案を出し、おすすめに★を付ける。決定は CD・Pr。
- 事実／【仮説】／【未確認】を区別して書く。出典を明記する。
- 「あえて好かれたい人」「あえて嫌われたい人」を書いて、ターゲットを絞る。
- 「言い換えルール」を決める（例：「挑戦」は学生に「よくあるワード」と言われたので、具体の動詞に置き換える）。
- 品質チェック（わかりやすい／新しい挑戦／本質的／妥協がない／貢献インパクト）と、自己チェック（不整合・リスク）を付ける。
- 未確認事項と次のステップで終える。

## 4. 「ニーズ」と「課題」は別（Slack #visions-project、10/5）
- **ニーズ**：先方の要望。SPD 1枚目に書く。
- **課題**：コミュニケーションの課題。SPD 2枚目の「顕在的な課題（＋仮説）」に書く。
- **ペルソナ**：浸透するうえでキーになる人。
- ペルソナの手前で「構造的にどんな環境下で、どんな壁があって、どんな気持ちで過ごしているか」を考える。ここが抜けると、クリエイティブジャンプしにくい。
- 企画の深さ＝体験の深さ＝ストーリーの深さ＝SPDの深さ（#visions-26ユニットリーダー、10/7のメモ）。
